# Two-second handover and actual collector names

Staff first select quantities and explicitly choose/enter the actual collector, then reserve the selection. No physical delivery is requested before the server confirms that reservation. The reserved screen has one deliberate hold action instead of a checkbox followed by Confirm. Holding for two seconds attests that the depositor/receipt was matched and these reserved passes were physically handed to that collector. Touch release/movement, changed intent, focus loss, backgrounding and navigation cancel an unfinished hold. Keyboard Space/Enter has the same timing; assistive activation provides a cancellable two-second equivalent without another checkbox.

The progress fill means only that the input gesture is progressing. It never means stock or handover is confirmed. The existing journal saves each operation before sending it. Release and handover retain their existing authoritative validation, request IDs, frozen quantities and recovery. Recovering a new reservation never automatically confirms physical delivery. Already-saved legacy physical attestations recover without asking staff to deliver passes again; a definitive rejection retains their original intent and requires supervisor reconciliation. Old clients/older pending records remain valid when a collector was not recorded.

`collector_label` already exists in collection/audit JSON; the Worker now validates and passes that optional field through rather than discarding it. New clients require a nonempty name. Lookup can offer names from the matching confirmed intake, scoped by workspace/deposit/booth, without exposing contact numbers or auto-selecting a person. A name is an annotation/physical check, not an authorization credential or per-person stock balance.

Confirmed partial/final drafts greet the configured update recipient by their own saved name and say who received the recorded quantities. A different unnamed contact never inherits the depositor's name. The completion view shows the depositor and actual collector separately. Original planned shares are not decremented by guessing who collected, and current group stock remains authoritative. Pending releases produce no completed-handover message.

No schema migration, provider, dependency or new custody API is introduced. Checks cover hold timing/cancellation, short taps, keyboard/assistive input, role labels, invalid names, permission scope, duplicate requests and recovery with the original collector intent. Physical touch/assistive behavior and audible output remain handset acceptance tasks.
