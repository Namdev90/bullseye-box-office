01 / CONNECTION

Wait for the local desk

No internet is needed to verify a code. The local server must still confirm release before any physical handover. If a response is lost, recover the identical saved request. Never start another release to replace an uncertain one.

02 / UNCERTAIN HANDOVER

Reserved is not handed over

A recorded release already subtracts its quantities from the balance. The original operator must inspect physical stock and the recorded categories. Hand over those reserved passes only once, or confirm if already handed over. If uncertain, stop and involve a supervisor. No automatic return, replacement, reset or undo.

03 / SHARING THE CODE

Show or tell the code privately

Show the private code on screen or read it quietly in three groups. Ask the depositor to repeat it back before closing, then have them share it with trusted friends. No printed receipt is needed. Anyone holding it can collect any remaining passes; it does not assign a quantity to a friend. WhatsApp needs a network and the recipient must actually receive the code. Opening a draft does not send or deliver it. Never write the code on a publicly visible envelope.

NFC: future option only. Not implemented or tested here. Desktop Chrome does not support Web NFC; supported Android tag workflows are not phone-to-phone sharing. Use private on-screen or verbal sharing instead. No offline NFC promise.

04 / FULL OUTAGE

Stop before switching systems

A supervisor must stop all digital releases before using a controlled paper ledger. Log packet ID, event, categories, quantity, staff label and time without public exposure of codes. Reconcile every action and physical stock before resuming. Restoring an old database can recreate already-collected balances. Paper reconciliation and failover are not implemented.

Demo boundaries

One trusted laptop. Use synthetic data. No default ID check, named collectors, individual allocation, remote synchronization, admission validation or code-replacement workflow. Staff labels and original-operator checks are procedural, not authentication. A lost code requires supervisor review outside this demo; packet ID alone cannot authorize release.
